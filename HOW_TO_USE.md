# How to Use System Monitor GUI

This guide walks through day-to-day usage of the app after it is built.

## 1) Launch the app

From the repository root:

```bash
./build/SystemMonitor
```

When the app opens, use the left sidebar to switch pages.

## 2) Understand each page

## Overview

Use this page for quick health checks:

- CPU overview (overall + per-core, frequency, load averages)
- Memory + swap usage
- Total network throughput
- 60-second history charts for CPU/memory/network/disk
- Snapshot export buttons:
  - **Export JSON snapshot** → `snapshot.json`
  - **Export CSV snapshot** → `snapshot.csv`

## Processes

Use this page to inspect active processes:

- Filter by process name or PID using the search field.
- Review PID, name, CPU%, and memory usage.
- Click **Kill** to request process termination.
- Confirm in the popup dialog before action is sent.

> Note: killing processes may require elevated permissions depending on OS/user.

## Disks

Use this page to inspect storage:

- Per-disk/mount usage
- Read throughput
- Write throughput

## Network

Use this page to inspect interfaces:

- Per-interface download and upload rates
- Total received/transmitted counters (MB)

## Settings

Use this page to configure behavior:

- **Refresh rate (ms)**: polling interval
- **Dark theme**: toggle dark/light appearance
- **Debug mode**: enables additional log verbosity
- **Units**: choose auto/metric presentation
- **Use mock data provider**: simulate metrics for unsupported environments
- **Apply provider change**: switch provider immediately
- **Save settings**: persist to `settings.conf`

## 3) Keyboard shortcut

- `Ctrl + E`: quick-export current snapshot to `snapshot.json`

## 4) Files generated by the app

- `snapshot.json` / `snapshot.csv`: exported snapshots
- `settings.conf`: persisted settings
- `system-monitor.log`: structured log output

## 5) Common workflow

1. Open **Overview** to confirm system collection is healthy.
2. Use **Processes** to identify CPU/memory-heavy tasks.
3. Inspect **Disks** and **Network** for bottlenecks.
4. Tune refresh/theme/debug in **Settings**.
5. Export JSON/CSV snapshots for sharing or recordkeeping.

## 6) If something looks wrong

- No data or odd values: enable **Use mock data provider** first to verify UI path.
- Process kill fails: retry with appropriate permissions.
- Logging needed: enable **Debug mode** and inspect `system-monitor.log`.
